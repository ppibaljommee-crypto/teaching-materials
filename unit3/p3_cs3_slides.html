👩‍🏫 ทบทวนว่า ป.2 ใช้ ScratchJr ป.3 ขึ้นมาใช้ Scratch ซึ่งทำได้มากกว่า

🤔 Scratch VS ScratchJr ต่างกันอย่างไร?

📱 ScratchJr (ป.2)

แท็บเล็ต/มือถือ อายุ 5-8 ปี

• บล็อกเล็ก ใช้การแตะ

• ตัวเลือกคำสั่งน้อยกว่า

• ไม่มีตัวแปร/เงื่อนไข

• สร้างการ์ตูนง่ายๆ

💻 Scratch (ป.3)

คอมพิวเตอร์ อายุ 8+ ปี

• บล็อกมากกว่า ทำได้ซับซ้อนกว่า

• มีตัวแปร เงื่อนไข ลูป

• สร้างเกมจริงได้

• แชร์ออนไลน์ได้

👩‍🏫 เปิด scratch.mit.edu บนจอใหญ่ แนะนำแต่ละส่วน ให้นักเรียนบอกชื่อตาม

🖥️ ส่วนประกอบของ Scratch

  • 1Stage — พื้นที่แสดงเกม/การ์ตูน (มุมขวาบน)
  • 2Sprite Panel — รายชื่อตัวละครทั้งหมด (ด้านล่าง Stage)
  • 3Block Palette — หมวดคำสั่งสีต่างๆ (ซ้าย)
  • 4Script Area — ลากบล็อกมาต่อกันที่นี่ (กลาง)
  • 5Green Flag ▶ — กดเพื่อเริ่มโปรแกรม (บน Stage)
👩‍🏫 อธิบาย Events เป็น "ประตู" ที่เปิดให้โปรแกรมเริ่มทำงาน ไม่มี Event = โปรแกรมไม่เริ่ม

🟡 Events — บล็อกเริ่มต้น

Events = เหตุการณ์ที่ทำให้โปรแกรมเริ่มทำงาน
เหมือน "ปุ่มสตาร์ท" ของสคริปต์

Events พื้นฐาน

🟡 เมื่อคลิก ⚑ — เริ่มเมื่อกดธงเขียว

🟡 เมื่อกดปุ่ม Space — เริ่มเมื่อกดคีย์บอร์ด

🟡 เมื่อคลิกตัวละคร — เริ่มเมื่อคลิก Sprite

ใช้งานในเกมจับผิด

• กดธงเขียว = เกมเริ่ม

• คลิกภาพที่ผิด = ได้คะแนน

• คลิกภาพที่ถูก = เสียคะแนน

👩‍🏫 แสดงบล็อก "ทำซ้ำตลอดไป" และ "ถ้า...ทำ" บน Scratch ให้นักเรียนดูรูปร่างบล็อก

🟠 Control — ควบคุมการทำงาน

🔄 Loop (วนซ้ำ)

ทำซ้ำ 10 ครั้ง
  [คำสั่ง]
จบ
ทำซ้ำตลอดไป
  [คำสั่ง]
จบ

🔀 If (เงื่อนไข)

ถ้า [เงื่อนไข] แล้ว
  [ทำสิ่งนี้]
จบ

ใช้ตรวจว่า "คลิกถูกภาพไหม?" แล้วค่อยบวกหรือลบคะแนน

👩‍🏫 อธิบายตัวแปรเหมือน "กล่อง" เก็บค่า เช่น คะแนน เปลี่ยนค่าได้ระหว่างเล่น

📦 ตัวแปร (Variable) — กล่องเก็บคะแนน

ตัวแปร = กล่องที่เก็บค่าได้ เช่น คะแนน เวลา จำนวนชีวิต
ค่าในกล่องเปลี่ยนได้ขณะเล่นเกม

สร้างตัวแปร Score

กำหนด Score = 0
เปลี่ยน Score โดย 1
เปลี่ยน Score โดย -1

ใช้ในเกมจับผิด

• เริ่มเกม → Score = 0

• คลิกถูก → Score +1

• คลิกผิด → Score -1

ติ๊กให้แสดง Score บน Stage ได้

👩‍🏫 สาธิตการสั่งให้ Sprite เดิน หมุน ไปยังจุด x,y บน Stage

🔵 Motion — การเคลื่อนที่

คำสั่งเคลื่อนที่พื้นฐาน

เดิน 10 ก้าว
หมุนขวา 15 องศา
ไปที่ x: 0 y: 0
เด้งขอบ

พิกัด x, y

Stage ขนาด 480×360

จุดกลาง = x:0, y:0

x+ = ขวา | x- = ซ้าย

y+ = บน | y- = ล่าง

ในเกมจับผิด: สุ่มตำแหน่งภาพ!

👩‍🏫 แสดงการเปลี่ยน Costume และการแสดง/ซ่อน Sprite ในเกม

🟣 Looks — รูปร่างและข้อความ

  • 1พูดว่า "..." — แสดงกล่องข้อความ (ใช้บอกคะแนน)
  • 2เปลี่ยน Costume — เปลี่ยนหน้าตาตัวละคร
  • 3แสดง / ซ่อน — ทำให้ Sprite ปรากฏหรือหายไป
  • 4เปลี่ยนขนาด — ทำให้ใหญ่ขึ้น/เล็กลง

ในเกมจับผิด: ใช้ "ซ่อน/แสดง" เพื่อทำให้ภาพปรากฏ-หายไป

👩‍🏫 Sensing = ประสาทสัมผัสของโปรแกรม รับรู้การคลิก การชน ปุ่มกด

🩵 Sensing — การรับรู้/ตรวจจับ

Sensing = บล็อกที่ทำให้โปรแกรม "รู้สึก/รับรู้" สิ่งที่เกิดขึ้น

  • 1แตะ Mouse-pointer? — ตรวจว่าเมาส์ชี้โดนตัวละครไหม
  • 2กดเมาส์? — ตรวจว่าผู้เล่นคลิกหรือยัง
  • 3แตะสี / แตะขอบ? — ตรวจการชนกัน

เกมจับผิด: ใช้ "ถ้าแตะ mouse-pointer และกดเมาส์" → ตรวจว่าคลิกภาพไหน

👩‍🏫 เสียงทำให้เกมสนุกขึ้น — สาธิตใส่เสียงตอนคลิกถูก/ผิด

🔊 Sound — ใส่เสียงให้เกมสนุก

คำสั่งเสียง

เล่นเสียง [pop]
เล่นเสียง [cheer] จนจบ
หยุดเสียงทั้งหมด

ใช้ในเกมจับผิด 🎵

✅ คลิกถูก → เสียง "ติ๊ง!" 🔔

❌ คลิกผิด → เสียง "บัซ!" 📯

🏆 ชนะ → เสียงเชียร์ 🎉

เลือกเสียงจากแท็บ Sounds

👩‍🏫 สาธิตสร้างเกมทีละขั้น ค่อยๆ อธิบาย ให้นักเรียนทำตาม

🎮 สร้างเกมจับผิดภาพ — ขั้นตอน

  • 1เพิ่ม Sprite 2 ตัว: ภาพที่ถูก และ ภาพที่ผิด
  • 2สุ่มตำแหน่งภาพด้วย ไปที่สุ่ม x/y
  • 3เมื่อคลิกภาพผิด → บวกคะแนน + พูด "ถูกต้อง!"
  • 4เมื่อคลิกภาพถูก → ลบคะแนน + พูด "ผิด!"
  • 5ตั้ง ตัวแปร Score แสดงคะแนน
👩‍🏫 อ่านสคริปต์ทีละบรรทัด ให้นักเรียนเข้าใจว่าแต่ละบล็อกทำงานอย่างไร

📜 ตัวอย่างสคริปต์: ภาพที่ผิด

นี่คือโค้ดของตัวละคร "ภาพผิด" ที่ผู้เล่นต้องคลิก

🟡 เมื่อคลิก ⚑

👩‍🏫 เชื่อมแนวคิด "คิดก่อนทำ" — นักออกแบบเกมวางแผนก่อนเขียนโค้ดเสมอ

🎨 วางแผนเกมก่อนสร้าง (Game Design)

ตอบ 4 ข้อนี้ก่อนเริ่มเขียนโค้ด

  • 1🎯 เป้าหมายเกม: ผู้เล่นต้องทำอะไรถึงชนะ?
  • 2🕹️ การควบคุม: ผู้เล่นคลิก/กดปุ่มอะไร?
  • 3🏆 การให้คะแนน: ได้คะแนนเมื่อไหร่ เสียเมื่อไหร่?
  • 4🎬 จบเกม: เกมจบเมื่อไหร่ (เวลาหมด/ครบคะแนน)?
